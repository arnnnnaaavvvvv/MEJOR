Frequently Asked Questions

Everything you need to know about arnav-audit architecture and engineering standards.

How does arnav-audit achieve zero external dependencies?
arnav-audit is written directly against the Node.js standard runtime APIs (fs, path, perf_hooks). By leveraging high-performance streaming regex engines and targeted AST heuristics, it eliminates the need for massive third-party parser trees, making it instantly executable on any system with Node >= 16.
Is my source code or proprietary IP ever transmitted anywhere?
Never. arnav-audit makes zero network requests, has no telemetry collection, and initiates zero external socket connections. All file reads and heuristic validations occur 100% within your local device's memory. It is fully approved for air-gapped defense networks and private corporate repositories.
How does the AI prompt generation (--prompts) work?
When run with --prompts (or --fix), arnav-audit groups detected violations by file path and line number, pairs each with its corresponding CWE/OWASP remediation rule, and formats the output into a structured markdown prompt optimized for LLMs like Cursor Composer, Claude Code, and Antigravity. You simply copy and paste the prompt into your AI agent to auto-fix the entire codebase.
Can arnav-audit be used as a pre-commit hook?
Yes! Because arnav-audit executes in under 15ms, it introduces zero noticeable delay during git commits. You can configure it inside Husky or standard .git/hooks/pre-commit to block developers from accidentally committing credentials, unmounted React listeners, or broken mobile viewport traps.
How does it detect subtle mobile UI and iOS auto-zoom traps?
Pillar 4 analyzes CSS, SCSS, and HTML styles against mobile platform constraints. For instance, iOS Safari forces a viewport zoom whenever an input font-size is smaller than 16px, breaking mobile layouts. arnav-audit flags these declarations, as well as missing touch-action: manipulation and destroyed keyboard :focus-visible indicators (WCAG 2.4.7).
